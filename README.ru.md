# sing-box для Keenetic / Netcraze

> [!IMPORTANT]
> Если ваш поставщик прокси использует Xray версии 26.9.8 или выше и не понимает, почему теряет существующих или не получает новых клиентов, а у вас тем временем возникают проблемы с подключением к узлам REALITY, попробуйте один из следующих отпечатков: `firefox`, `safari`, `random` или `randomized`. Отпечатки `chrome` и `random` использовать не рекомендуется.
>
> Во всех остальных случаях используйте официальные бинарные файлы sing-box.

Сборки sing-box для роутеров Keenetic и Netcraze с дополнительными патчами.

Это не исходный код upstream `sing-box`, а релизный проект для сборки готовых бинарников под архитектуры, которые обычно используются в маршрутизаторах семейства Keenetic / Netcraze. Основная цель — собрать sing-box с нужными тегами и патчами, проверить REALITY ClientHello и опубликовать готовые артефакты в GitHub Releases.

[English version](README.md)

## Что это за проект

Репозиторий автоматически:

- получает нужную версию upstream `SagerNet/sing-box` по тегу;
- загружает и применяет дополнительные патчи из внешних источников;
- проверяет применимость каждого патча перед его применением;
- собирает бинарники под целевые архитектуры;
- добавляет необходимые `build tags`;
- при необходимости сжимает бинарники с помощью `UPX`;
- проверяет, что собранный бинарник проходит REALITY-проверку;
- публикует результаты в GitHub Releases.

## Поддерживаемые сборки

В GitHub Actions собираются бинарники для следующих конфигураций:

- `linux/arm64` + `musl`
- `linux/mipsle` + `softfloat` + `musl`
- `linux/mips` + `softfloat`

Для `arm64` и `mipsle` дополнительно включаются теги:

- `with_naive_outbound`
- `with_musl`

Для всех сборок используется набор общих тегов:

- `with_quic`
- `with_utls`
- `with_clash_api`
- `badlinkname`
- `tfogo_checklinkname0`
- `with_gvisor` для стабильных релизов

UPX-версии публикуются с суффиксом `_upx`.

## Применяемые патчи

Патчи загружаются из внешних репозиториев и применяются к исходному коду upstream `sing-box`.

Перед применением каждого патча выполняется проверка совместимости с текущим исходным кодом с помощью `git apply --check`. Если проверка проходит успешно, патч применяется. При ошибке загрузки, проверки или применения сборка завершается с ошибкой.

Применяемые патчи:

- `0001-reality-keep-X25519MLKEM768-key-share-announce-clien.patch`
- `0002-utls-firefox-Firefox-148-safari-Safari-26.3-as-Xray-.patch`
- `0010-utls-keep-the-randomized-fingerprint-consistent.patch`

Источник патчей: [FiyeroT/podkop-engine](https://github.com/FiyeroT/podkop-engine), подробности читайте там.

Список патчей может расширяться. Их источники указываются по мере добавления.

## Проверка перед релизом

Workflow [.github/workflows/build.yml](.github/workflows/build.yml) выполняет проверки перед публикацией:

1. Загружает официальный upstream `sing-box` для выбранной версии.
2. Проверяет применимость дополнительных патчей и последовательно применяет их.
3. Проверяет исходный, неподпатченный бинарник на этапе REALITY-тестирования.
4. Собирает бинарники с применёнными патчами.
5. Запускает проверку через [.github/verify/reality/verify.sh](.github/verify/reality/verify.sh).
6. Публикует артефакты в GitHub Releases при успешном прохождении предусмотренных проверок.

Это помогает обнаруживать несовместимость патчей с выбранной версией upstream и снижает риск публикации бинарников, не проходящих REALITY-тестирование.
